## 🔍 Problem Framing

### Le paradoxe Wix
**Promesse** : "Tout-en-un, clé en main"  
**Réalité** : 
- Machine à gaz non optimisée
- Investissement cognitif fort (tout paramétrer, tout gérer)
- Coût élevé pour features peu/pas utilisées
- Bugs + limitations structurelles
- Dépendance propriétaire

### La proposition alternative
**"Rien que ce qu'il faut, tout ce qu'il faut"**

- Solution sur-mesure métier
- Ownership des données (même si clients s'en foutent du RGPD 😅)
- Compréhension métier intégrée
- Autonomie utilisateur préservée (CMS accessible)
- Coût : Plus cher court terme, moins cher long terme (5 ans ?)

**Point de friction identifié** : L'argument "rentable à 5 ans" est peu vendeur.

## ✅ Critères de Réussite (Janvier 2026)

### 1. Satisfaction utilisateur (Jezabel)
- "C'est aussi beau qu'avant"
- Autonomie préservée (édition sans friction)
- Ne sollicite que pour upgrades majeurs

### 2. Maîtrise technique (IRIM)
- Configuration intuitive (fini les 10 min à chercher où c'est)
- Code propre, maintenable, documenté
- Fier du travail (corrélé aux vrais besoins métiers)

### 3. Expérience client final (patients)
- Flow sans friction : Visite → Découvre → Réserve → Paye → Vient en séance
- Rassurance (qui est la thérapeute, ce qu'elle fait)
- Lien maintenu avec thérapeute

### 4. Qualité pro (baseline)
- Technologies récentes
- Site optimisé (perf + SEO + accessibilité)
- **Lighthouse 4×100%**
- Code maintenable et scalable

## 🚨 Risques Identifiés

### Risque #1 : Feature Creep
**Symptôme** : Dérive scope, ajout features non-essentielles  
**Parade** : Itérations client + user, validation continue, scrum-like sans dogme

### Risque #2 : Temps disponible
**Contexte** : Projet "d'après" ou "d'après l'après"  
**Parade** : Consignation claire vision (ce doc), reprise facile dans 3-6 mois

### Risque #3 : Surinvestissement émotionnel
**Enjeu** : Projet vitrine #1 + relation conjugale  
**Parade** : Différenciation époux/dev validée, relation stable
